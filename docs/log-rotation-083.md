# 0.8.3 日志规则

## 默认行为

- 应用日志：`logs/oneproxy-YYYY-MM-DD.log`；核心日志：`logs/singbox-YYYY-MM-DD.log`。日期取机器本地时间，在下一次非空写入时切换日期。
- 两流统一 **64 MiB（67,108,864 字节）/文件**，不是预分配。达到上限后的下一字节触发轮转；同一天保留当前文件及 `.log.1`、`.log.2`、`.log.3`，`.1` 最新，`.3` 最旧。再轮转时删除最旧分卷。
- 大单次写入按剩余容量切片，不按行截断或随意舍弃；多字节字符/单条记录可跨文件。一次写入超过四份容量时，较早部分会按相同三分卷保留规则淘汰。
- 保留今天及前 **4 个本地自然日**，不是过去 120 小时。启动、跨日时清理；正常同日不逐次扫描。清理失败仅在后续写入时按最多每小时一次重试，无后台线程；无写入无需即时清理。
- 仅清理本流前缀、真实有效的 `YYYY-MM-DD` 和精确 `.log` / `.log.1`–`.log.3` 命名的普通文件。其他流、无效日期、额外后缀、`.4`、`.01`、目录、符号链接及未来日期不删除。跨月、跨年、闰日按日历计算。

## 遗留与故障边界

- **旧的 `oneproxy.log`、`singbox.log`、无日期分卷、任何 `.oversized` 及未知文件均不删除、改名、截断或迁移。** 本版本不生成压缩、归档或 `.oversized`，不读取/搬迁用户的大历史日志。
- 异常超限的日期文件（包括过期日期文件和分卷）也不自动删除或移动。当前日期文件/待轮转分卷异常超限时写入返回错误，下一本地日期仍可正常写新文件；没有额外保全框架。
- 理论新命名正常文件上界为 `64MiB × 4份 × 5天 × 2流 = 2560MiB`。不含旧文件、未知文件、未来日期、外部写入导致的超限文件及暂时无法删除的文件。机器日期大幅倒退时，未来日期文件同样保留，不能承诺上述上界覆盖该情况。
- 同一个逻辑路径只允许一个 Writer 所有者。应用内部写入互斥；重启追加当天文件并读取实际大小。轮转先关闭自己的句柄，按磁盘上的空分卷位置继续，支持 Windows 改名锁失败/重启后的重试，不重复移动或误删存活分卷。
- 写失败返回已落盘字节数和错误，后续写入最多每秒尝试恢复一次；不缓存无限数据。故障期间无法落盘的数据可能丢失，但核心 stdout/stderr 始终继续排空，不因日志失败停止核心。保留现有核心故障提示和私有 4KiB 启动/退出诊断尾部；不再注入旧的恢复字节计数记录。
- `GetLogs` 的 Windows 读取句柄允许共享删除，不阻挡轮转改名。运行时读取 Writer 最近使用的日期文件；无 Writer 时读取今天日期文件。退出/Check 后仍优先读取本次进程的私有尾部，不回退读取旧无日期文件。跨大小分卷时不额外拼接历史文件。

## 验证

测试仅用临时目录、注入时钟及小阈值（异常文件测试用临时稀疏文件），不等待真实跨日，不操作安装实例。覆盖日期切换、五天/跨月/闰日/跨年/DST、本流精确命名、未知/旧/超限文件不动、重启续写、轮转中途重启、大写入字节连续性、并发、写入/重开错误、Windows 活动文件/分卷锁与清理重试、核心持续排空及启动诊断隐私。

```powershell
go test ./internal/logger ./internal/proxy -count=1
go test -race ./internal/logger ./internal/proxy -count=1
go test ./cmd/oneproxy ./cmd/oneproxy-dll -count=1
pwsh -NoProfile -File scripts/test-release-version.ps1
```

DLL/安装器版本 `0.8.3`，Windows 资源 `0.8.3.0`。`build.ps1` 继续以安装器元数据生成 Qt/DLL 资源、DLL 版本、安装器名及哈希清单；签名脚本默认路径为 `dist/OneProxy-0.8.3-setup.exe`。最终安装包由独立审核合并后在主仓构建，本实施不安装、不停止现有代理、不 push。
